# Notification Sender Service

A decoupled, standalone Node.js service for processing message queue items generated by external applications and dispatching notifications through pluggable transmission providers (WhatsApp Web, Telegram, Meta API, Email, SMS).

---

## 🏛 Architecture Overview

The `notification-sender` service is designed around clean separation of concerns and provider isolation:

- **GoogleSheetService**: Data Access Layer responsible strictly for reading and writing queue statuses in Google Sheets. Completely decoupled from notification logic.
- **QueueService**: High-level queue state orchestrator (`readPendingQueue`, `markProcessing`, `markSent`, `markFailed`, `updateRetry`).
- **NotificationDispatcher**: Pure routing engine accepting normalized Queue Objects (`Queue_ID`, `Recipient`, `Message`, `Provider`, `Status`) and delegating delivery to the target provider.
- **Providers**: Independent, pluggable communication channels (`WhatsAppWebProvider`, `TelegramProvider`, `MetaProvider`, `EmailProvider`, `SMSProvider`).
- **ConfigService**: Configuration manager parsing `.env` and environment variables.
- **Logger**: Dual-channel logger supporting `DEBUG`, `INFO`, `WARN`, `ERROR` output to console and file.

## 🔄 Execution Flow

```text
Google Sheet (Message_Queue)
          │
          ▼
   GoogleSheetService (Fetch Pending Rows)
          │
          ▼
     QueueService (Filter & Map Queue Records)
          │
          ▼
 NotificationDispatcher (Route by Provider Name)
          │
  ┌───────┼───────────────┬───────────────┐
  ▼       ▼               ▼               ▼
WhatsApp Telegram      Meta API         Email / SMS
Provider Provider      Provider          Provider
  │       │               │               │
  └───────┴───────────────┴───────────────┘
          │
          ▼
  QueueService (Mark Status: SENT / FAILED)
          │
          ▼
   GoogleSheetService (Batch Write Status)
```

## ⚙️ Installation & Configuration

1. Clone or navigate to the `notification-sender` directory.
2. Copy `.env.example` to `.env`:
   ```bash
   cp .env.example .env
   ```
3. Configure environment variables in `.env`:
   ```env
   GOOGLE_SHEET_ID=your_spreadsheet_id
   GOOGLE_SERVICE_ACCOUNT=path_to_key.json
   QUEUE_SHEET=Message_Queue
   POLL_INTERVAL=30
   DEFAULT_PROVIDER=WHATSAPP_WEB
   LOG_LEVEL=INFO
   LOG_FILE_PATH=./logs/app.log
   ```

## 🔌 Future Providers

Adding a new notification channel requires zero changes to core queue or Google Sheet services:
1. Create a provider class in `src/providers/` implementing `initialize()` and `send(recipient, message)`.
2. Register the provider instance in `NotificationDispatcher` via `registerProvider('NAME', instance)`.
